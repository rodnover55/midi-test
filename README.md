# MIDI-монитор Quad Cortex / HX Stomp

Показывает входящий MIDI-поток для двух гитарных процессоров:

- **Neural DSP Quad Cortex** (CorOS 4.1.1), по умолчанию канал 2;
- **Line 6 HX Stomp** (прошивка 3.80), по умолчанию канал 1.

Оба устройства нарисованы как настоящие: корпус, экран, футсвитчи, подсветка. Их состояние меняется по входящим сообщениям так, как его изменила бы прошивка: пресеты, банки и сетлисты, сцены и снапшоты, режимы футсвитчей, тюнер, Gig View, лупер, tap tempo, MIDI Clock, экспрессия и остальные команды MIDI-реализации. Под устройствами — журнал мониторинга. В каждой записи: время получения с миллисекундами, интервал от предыдущей записи, порт, канал, сырые байты, общее описание сообщения и команда, которую сообщение выполняет на каждом процессоре. Команда помечается, если процессор её игнорирует, ждёт следующего сообщения или вообще не поддерживает.

Чего приложение не знает, оно не выдумывает: имена пресетов, содержимое цепочки и назначения футсвитчей по MIDI не передаются, поэтому на экранах вместо них стоят «—» и пустые слоты.

## Запуск

Это статичная страница: сервер не нужен, MIDI принимает сам браузер через Web MIDI API.

```sh
npm install --legacy-peer-deps   # системный npm 9.2 падает на разрешении peer-зависимостей без флага
npm run build                    # статичные файлы в dist/
npm run preview                  # раздача dist/ на http://localhost:5180/
```

Собранную `dist/` можно раздавать любым веб-сервером. Web MIDI работает только на https или на localhost, поэтому открыть `index.html` прямо из файла нельзя. Для разработки есть `npm run dev`: страница пересобирается на лету.

При первом открытии браузер спросит разрешение на доступ к MIDI-устройствам.

**Браузер.** Нужен Chrome или Chromium, установленный не из snap, либо Firefox. Chromium и Firefox из snap не имеют доступа к ALSA (звуковой подсистеме Linux), и Web MIDI в них не работает. Firefox из snap получает доступ к ALSA после подключения интерфейса `firefox:alsa` командой `snap connect` с правами root; затем Firefox попросит разрешение на MIDI для сайта.

## Откуда берётся MIDI

Страница слушает все MIDI-входы, которые видит браузер, включая подключённые позже. Чтобы видеть поток из DAW (например, REAPER) без MIDI-интерфейса, направьте её MIDI-выход в системный порт «Midi Through». Если браузер показывает и собственный выход DAW, не включайте оба порта сразу, иначе каждое сообщение придёт дважды.

## Настройки

Кнопка «Настройки» в правом верхнем углу открывает:

- **MIDI-входы** — включение и выключение каждого порта;
- **каналы устройств** (1–16 или Omni) — их можно менять и прямо в заголовке панели устройства;
- **глобальные настройки приборов**, влияющие на обработку MIDI. У Quad Cortex это Ignore Duplicate PC, MIDI Clock In, слоты режимов и другие. У HX Stomp — приём PC и MIDI Clock, функции FS3–FS5, правка снапшотов и другие;
- **журнал** — его размер и запись каждого Timing Clock и Active Sensing. По умолчанию эти сообщения только подсчитываются: темп MIDI Clock виден в заголовке.

Настройки сохраняются в браузере. Журнал и состояние устройств живут, пока открыта вкладка. Кнопка «Сброс» на панели устройства возвращает его в состояние после включения.

## Проверка без процессоров

```sh
npm run send -- pc 1 122 cc 1 69 1 cc 2 43 2 clock 120 5
```

Команда отправляет сообщения в «Midi Through», который слушает страница: Program Change, Control Change, ноты, MIDI Clock, сырые байты (`hex "F0 7E 7F 06 01 F7"`), паузы. Полный список — в `scripts/send.ts`.

Чтобы посмотреть устройство в любом состоянии без MIDI, откройте страницу предпросмотра в режиме разработки: `/preview.html?device=qc&midi=B1 2B 02;C1 05` (параметры описаны в `src/ui/preview/main.tsx`). Описания команд и итоговое состояние в текстовом виде печатает `npx tsx scripts/replay.ts hxstomp 'C0 7A;B0 45 01'`.
